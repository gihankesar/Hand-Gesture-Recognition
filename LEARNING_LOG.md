# Learning log

## 1. From finger count to anatomical features

**Change and reason.** The original dot-product angle, index base and distal angles, thumb IP angle, thumb direction, and palm-normalized pinch distance are retained in `gesture/geometry.py`. Floating-point coordinates preserve small movements lost to pixel rounding. The four long fingers now each have a PIP and DIP angle. Keeping identity lets an index point differ from a fist even when only one finger is straight.

**Mathematics and operation.** At joint B, normalize A−B and C−B, clip their dot product to [−1,1], then apply arccos and convert to degrees. Straight bones give approximately 180°. Translate by the wrist and divide lengths by the index-to-little MCP span. Translation and uniform scaling cancel. The thumb IP angle describes extension, its palm-relative direction and tip-to-middle-MCP reach describe posture, and its tip-to-index gap approximates opposition. Distances cannot prove physical contact. Invalid segments or an extremely narrow projected palm reject the entire feature vector. This deliberately trades coverage for fewer accidental messages.

**Decision rule.** A straight finger requires both joints above or at the straight threshold. A curled finger requires its PIP at or below the curled threshold. The gap between thresholds allows abstention. Pinch gets priority and requires at least two extended non-index fingers. Fist also constrains thumb reach. V Sign requires tip spread. The numbers are engineering starting points. Printing a feature does not establish its predictive power.

**Evidence and next study.** Unit tests exercise 0°, 90°, 180°, invalid inputs, palm normalization, reflection, all labels and boundary cases. The original application also passed a blank-frame and two-open-palms smoke check before refactoring. Study projection versus Euclidean angles, the MediaPipe landmark index chart, and how a confusion matrix changes as thresholds move. Try the same tilted pose in each geometry mode before choosing a threshold.

## 2. From frame labels to messages

**Change and reason.** A new confirmation state machine consumes the list of labels and a monotonic millisecond timestamp. A message must represent an intentional hold. A single video frame is weak evidence, and consecutive video frames are correlated.

**Algorithm and operation.** A change of candidate restarts a stopwatch. Only an uninterrupted single recognized label can reach the hold duration. Emission latches the output until continuous observed absence reaches the release duration. An unknown pose or a second hand interrupts a pending hold and preserves any existing latch. A frame gap above the configured limit breaks accumulated evidence. This design lets two people enter the picture without a detection-list index switching speakers mid-hold when both are visible. It cannot identify a person silently replacing another between sampled frames. A hand temporarily lost for the entire release duration is indistinguishable from intentional withdrawal.

**Verification and study.** Timestamped unit sequences cover exact boundaries, brief and prolonged absence, a second hand, a stalled camera, and repeating a gesture after release. Tests check both the emitted events and transcript correction. Study finite-state machines, signal debouncing, and the difference between per-frame accuracy and duplicate messages per minute. Trace a hold, a 100 ms dropout and a return on paper.

## 3. Connecting inference, replay and communication

**Change and reason.** The original entry point still opens camera 0, converts BGR to RGB, calls the bundled MediaPipe VIDEO landmarker for up to two hands, and draws its connections. Camera ownership moved inside the runner so importing the angle helper does not start a capture. The next-frame measurement key now compares all three coordinate systems. The previous trial could succeed for a stationary hand before the user reacted. Its replacement requires an empty frame after the cue, then a confirmed Open Palm before the deadline. It measures a prompted task including the hold and the person's response.

**Algorithm and operation.** Capture and replay both call observe, classify and the same confirmation state machine. The live clock samples monotonic time after camera read. Replay assigns frame i the media time round(1000 i / FPS), so machine speed cannot change the dwell requirement. The world-landmark path uses the model's separate world output. It does not manufacture a depth measurement when that output is missing. Nearly parallel palm axes are rejected by measuring the component of the unit longitudinal axis perpendicular to the lateral axis. One event appends one editable phrase to an in-memory transcript. Optional speech receives text via stdin in a local child process. A newer phrase supersedes unfinished speech.

**Verification.** Tests run the public entry point on a generated blank video with the actual model, verify timestamps and silence, and inject a known pose and keyboard events to check the preview controls. A separate 53-frame constant-rate clip derived from one available two-palm photo exercised blank, two hands, one held palm, withdrawal and repetition. The 2D and image-relative 3D runs each emitted exactly two greetings at media times 2100 and 4400 ms. World-landmark mode returned Unknown throughout the hand-present segments. On the original photo its two index PIP estimates were about 111° and 106°, below the 155° straight cutoff. This is evidence about one image and this model/threshold combination. It cannot rank methods across users or measure live latency.

**Study.** Compare normalized image x/y/z with world landmarks; then follow one frame from VideoCapture to a transcript entry. Explain why capture-to-display latency, cue-to-message time and media timestamps answer three different questions.

## 4. Testing a recognition claim

**Change and reason.** The suite now exercises complete 21-point synthetic hands for each rule, a projection counterexample and speech failure handling. The evaluation record separates those reproducible checks from model-output fixtures and from live user validation. The setup guide documents the CPU path, controls, adjustable rules and replay format.

**Mathematics and operation.** The endpoints (−1, 0, 1) and (1, 0, 1) relative to an origin joint have zero dot product in 3D, so the angle is 90°. Their 2D projections point in exactly opposite directions, giving 180°. A correct 2D angle computation can still misrepresent the hand in space. Conversely a model's estimated depth can distort angles. Evaluate both on identical inputs. At the message level, match intentions and confirmations one-to-one. A long held pose yielding fifty correct frame labels still represents a single intended message.

**Evidence.** A fresh install of the manifest passed 21 automated tests. The upstream reference fist passed the world-coordinate rule; the named point and V examples were rejected at the default straight cutoff. Inspecting individual joints revealed why. Lowering the threshold to 140° recovered both on these same development examples. That exercise diagnoses sensitivity, and collecting fresh users is necessary to establish any generalization benefit. Speech tests simulate a missing executable and a backend failure. Hearing a spoken phrase remains a hardware test.

**What to study next.** (1) Draw the landmark indices and calculate one PIP and DIP angle by hand. (2) Compare image and world measurements with the measurement key as you rotate a hand. (3) Trace the hold/release state machine using a replay trace. (4) Annotate a small clip before examining its predictions. (5) Build participant-separated confusion matrices and count unintended messages at rest. (6) Consider a trained classifier only once you can explain where the rule baseline succeeds and fails. See EVALUATION.md for the field protocol.
